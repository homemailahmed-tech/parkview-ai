# Meta models: what we researched, what we use, and why

Researched 1 Nov 2026. The primary source is Meta's model cookbook on GitHub (`meta-models/meta-model-cookbook`, read directly). Secondary sources are web listings; they are marked as such. `dev.meta.ai` itself could not be reached from the build environment.

| Model | What we verified | Evidence | Used in ParkView AI? | Why / why not |
|---|---|---|---|---|
| **Muse Spark 1.3** (`muse-spark-1.3`) | Chat Completions at `https://api.meta.ai/v1/chat/completions`, Bearer key. `response_format` JSON schema with constrained decoding; tool calling (`tool_choice` "auto" only); `reasoning_effort` | Cookbook `01_api_fundamentals` (03 tool calling, 04 structured output, 06 reasoning tokens). **Our live calls:** HTTP 200, served `muse-spark-1.3` ([LIVE_META_VERIFICATION.md](LIVE_META_VERIFICATION.md)) | **Yes, core** | Enquiry interpretation (structured facts + clarifying questions), clarification replies, option explanations, greeting, concierge intent |
| **Muse Voice Transcribe 1.0** (`muse-voice-transcribe-1.0`) | `POST https://api.meta.ai/v1/asr/transcribe`, Bearer key; multipart: JSON part `request` `{mode, model, audioEncoding:"WAV", languageBias?, keywords?}` plus part `audio`. Mono 16-bit WAV at 16 or 24 kHz; ≤ 10 min / 32 MB. Modes PUSH_TO_TALK / ENDPOINTING / DIARIZATION. Realtime WebSocket `/v1/asr/realtime` also exists. Response `{sessionId, transcript, audioDurationMs, turns?}` | Cookbook `06_muse_voice/01_voice_api_fundamentals/utils.py`. Price **$0.18 per audio hour** (Meta developer model page, via search). "25 languages" (cookbook). The list was not read, so South African languages are **unverified** | **Yes**: push-to-talk dictation of enquiries | Owners receive voice notes and phone calls. We use the file endpoint (simple, no WebSocket); 16 kHz WAV is encoded in the browser |
| Muse Wonder (`muse-wonder-1.0`) | Larger reasoning model, preview | Secondary listings only: about $4 / $20 per M tokens in/out, about 5× Spark's output price | No | Spark already handles the task; Wonder would add cost and latency without measured benefit |
| Muse Image | `POST /v1/images/generations` and `/v1/images/edits` | Cookbook `05_muse_image`; Meta developer blog via search (about $0.01/image) | No | Generated images must never stand in for real rooms. Marketing images are a possible future, clearly labelled |
| SAM 3.1 | Segmentation and tracking | Cookbook `07_sam` exists; hosted API details not verified | No | Segmentation cannot prove a room is clean or ready; no safe use before the deadline |
| Muse Spark Open / Meta open-weight models | OpenAI-compatible hosts (Groq, OpenRouter, Fireworks, Baseten, …) | Secondary listings | Supported as a configuration option, not used | One provider keeps the demo simple; the switchboard keeps the option open |
| Muse Code | Coding assistant (subscription) | Secondary | No | Not part of the product; this project was coded with Claude Code (disclosed) |

**Text-to-speech:** none of the sources above document a Meta speech-synthesis model. ParkView AI does **not** speak. If added, browser speech synthesis would be labelled as non-Meta.
